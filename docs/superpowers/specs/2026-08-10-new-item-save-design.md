# 새 항목 저장 설계

## 목표

통합 새 항목 화면에서 입력한 일정 또는 Todo를 기존 로컬 저장 경로에 실제로 저장한다.
저장에 성공하면 사용자가 들어왔던 캘린더 화면으로 돌아가며, Today 데이터는 다시 조회되어
방금 만든 항목이 즉시 보인다.

## 범위

이번 변경은 다음 동작만 포함한다.

- 제목, 고정 날짜, 항목 종류, 카테고리, 시간 형태를 `CreateTaskParams`로 변환한다.
- 유효한 폼에서만 저장 버튼을 활성화한다.
- 저장 중 중복 제출을 막고 진행 상태를 표시한다.
- 저장 실패 시 입력을 유지하고 재시도 가능한 오류를 표시한다.
- 저장 성공 시 Today 데이터를 무효화하고 원래 캘린더 경로로 돌아간다.

알림, 반복, 카테고리 관리, 수정·삭제, 저장 완료 토스트는 포함하지 않는다.

## 검토한 접근

### 1. 기존 화면 상태와 주입 가능한 저장 함수 사용

`NewItemPage`가 현재의 제목, 일정 종류, 카테고리, 시간 상태를 계속 소유한다. 제출할 때만
도메인 파라미터로 변환하고 `CreateTaskUseCase`를 호출한다. 테스트에서는 저장 함수를 주입해
정확한 파라미터와 비동기 상태를 검증한다.

변경 범위가 작고 현재 화면 구조를 보존할 수 있어 이 방식을 선택한다.

### 2. 새 항목 폼 전체를 전용 ViewModel로 이동

향후 알림과 반복 입력까지 한 번에 관리하기에는 유리하지만, 이미 동작하는 화면 상태를 모두
옮겨야 해 이번 PR의 크기와 회귀 위험이 커진다.

### 3. 라우터가 폼 변환과 저장을 모두 담당

화면을 단순하게 유지할 수 있지만 라우터가 UI 입력 규칙과 도메인 변환을 알아야 하므로 책임이
뒤섞인다.

## 폼 유효성

저장 버튼은 다음 조건을 모두 만족할 때 활성화한다.

- 앞뒤 공백을 제거한 제목이 비어 있지 않다.
- 시간 지정 항목은 시작 시각과 종료 시각이 모두 선택되어 있다.
- 종료 시각은 시작 시각보다 늦다.
- 종일 일정 또는 시간 없음 Todo는 별도 시각 없이 유효하다.
- 저장 요청이 진행 중이지 않다.

카테고리는 선택 사항이다. 카테고리 목록이 비어 있거나 조회에 실패해도 `카테고리 없음`으로
저장할 수 있다.

## 도메인 변환

제목은 앞뒤 공백을 제거한 값을 저장한다. 날짜는 선택된 로컬 날짜의 자정으로 정규화한다.
시간 지정 항목의 시작·종료 시각은 이 날짜와 선택된 `TimeOfDay`를 결합한다.

| 화면 상태 | `TaskKind` | `hasTime` | `isAllDay` | 시작·종료 |
| --- | --- | --- | --- | --- |
| 시간 지정 일정 | `event` | `true` | `false` | 선택 시각 |
| 종일 일정 | `event` | `false` | `true` | `null` |
| 시간 지정 Todo | `todo` | `true` | `false` | 선택 시각 |
| 시간 없음 Todo | `todo` | `false` | `false` | `null` |

선택된 카테고리 ID는 그대로 전달하며 `카테고리 없음`은 `null`로 전달한다.

## 저장 흐름

1. 사용자가 활성화된 저장 버튼을 누른다.
2. 화면이 즉시 저장 중 상태로 전환되어 추가 입력과 중복 제출을 막는다.
3. 현재 폼을 `CreateTaskParams`로 변환해 `CreateTaskUseCase`를 호출한다.
4. 실패하면 저장 중 상태를 해제하고 폼 안에 오류를 표시한다. 기존 입력은 모두 유지한다.
5. 성공하면 `onSaved` 콜백을 호출한다.
6. 라우터 계층은 `TodayViewModel`을 무효화한 뒤 기존 `from` 경로로 이동한다.

Today 이외의 Week·Month 화면은 아직 실데이터 화면이 아니므로 별도 ViewModel 갱신을 추가하지
않는다. 다만 저장 성공 후 복귀 위치는 기존 규칙대로 보존한다.

## 오류와 접근성

- 저장 실패 문구는 `항목을 저장하지 못했습니다. 다시 시도해 주세요.`로 통일한다.
- 오류 영역은 live region으로 노출해 스크린 리더가 새 오류를 알 수 있게 한다.
- 저장 중에는 버튼 문구를 `저장 중`으로 바꾸고 작은 진행 표시를 함께 노출한다.
- 실패 후 저장 버튼은 다시 활성화되어 같은 입력으로 재시도할 수 있다.
- 화면이 dispose된 뒤 완료된 비동기 결과는 UI 상태나 이동을 변경하지 않는다.

## 구조

- `NewItemPage`는 기존 폼 상태, 유효성 계산, 도메인 파라미터 변환, 제출 상태를 관리한다.
- 실제 앱에서는 Riverpod의 `CreateTaskUseCase`를 사용한다.
- 위젯 테스트는 선택적 저장 함수 주입점을 사용해 데이터베이스 없이 제출 결과를 검증한다.
- `app_router.dart`는 저장 성공 콜백에서 Today 상태 무효화와 원래 경로 복귀만 담당한다.

별도 폼 ViewModel이나 생성 컨트롤러 파일은 이번 범위에서 추가하지 않는다.

## 테스트

- 제목과 시간 상태에 따른 저장 버튼 활성화·비활성화를 검증한다.
- 네 가지 시간 형태가 정확한 `CreateTaskParams`로 변환되는지 검증한다.
- 제목 trim과 nullable 카테고리 전달을 검증한다.
- 진행 중 중복 탭이 한 번의 저장만 실행하는지 검증한다.
- 실패 시 오류 표시, 입력 보존, 재시도를 검증한다.
- 성공 시 원래 화면으로 복귀하고 Today 데이터가 다시 조회되는지 검증한다.
- 전체 Flutter 테스트, 분석, 포맷, `git diff --check`와 390x844 웹 화면을 검증한다.

## PR 경계

설계·계획 문서, 화면, 라우터, 관련 테스트와 모바일 증거 이미지만 한 PR에 포함한다. 변경 파일은
최대 7개로 제한하고 각 파일은 별도 커밋으로 올린다. PR은 리뷰 전 병합하지 않는다.
