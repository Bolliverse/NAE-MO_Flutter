# Daily Split View 설계

## 1. 목적

기존 Today 화면을 대체하는 두 번째 Daily 후보를 구현한다. 한 날짜의 일정과
Todo를 동시에 유지하면서, Calendar와 Todo 중 하나를 넓게 보고 반대쪽은
색상 중심의 좁은 미리보기로 남긴다.

이 설계는 사용자가 제공한 초기 스케치의 시각 언어를 따른다. 흰 배경, 얇은
시간 구분선, 단순한 날짜 이동, 카테고리 색상 블록, 최소한의 그림자를 사용하고
Material 기본 카드와 보라색 강조는 사용하지 않는다.

## 2. 확정된 화면 구조

화면은 위에서 아래로 세 영역을 가진다.

1. 공유 날짜 헤더
2. 고정 요약 영역
3. 세로 스크롤 시간 영역

공유 날짜 헤더는 `‹  12/18  ›` 형태로 화면 상단에 고정한다. Calendar와 Todo는
항상 같은 선택 날짜를 사용한다. 날짜는 좌우 화살표로만 이동하며, 좌우 스와이프는
Calendar/Todo 전환에만 사용한다.

고정 요약 영역에서 Calendar는 종일 일정을, Todo는 시간 없는 Todo를 표시한다.
시간 영역만 세로로 스크롤하며 두 패널은 항상 같은 시간 위치를 보여준다.

주간·월간 전환 메뉴는 이번 구현 범위에 포함하지 않는다. 향후 날짜 헤더를
확장할 수 있도록 날짜 헤더의 책임과 패널 전환 책임은 분리한다.

## 3. 패널 전환

기본 너비 비율은 다음 두 안정 상태를 사용한다.

- Calendar 활성: Calendar 82%, Todo 18%
- Todo 활성: Calendar 18%, Todo 82%

사용자가 좌우로 드래그하면 두 패널의 너비가 연속적으로 변한다. 손을 놓으면
진행도와 드래그 속도를 기준으로 가까운 안정 상태에 스냅한다. 좁은 패널을 탭하면
그 패널이 확대된다.

가로 드래그와 세로 스크롤은 Flutter의 제스처 방향 판정을 사용해 분리한다.
세로 움직임은 시간 영역 스크롤로, 가로 움직임은 패널 전환으로 처리한다.

## 4. 넓은 패널과 좁은 패널

넓은 Calendar 패널은 종일 일정의 제목과 카테고리 색상, 시간 일정의 시작·종료
시간과 제목을 표시한다. 넓은 Todo 패널은 시간 없는 Todo의 체크 상태와 제목,
시간이 지정된 Todo의 시간·체크 상태·제목을 표시한다.

좁은 패널은 넓은 UI를 단순 축소하지 않는다. 텍스트와 체크박스를 숨기고 아래
정보만 전달한다.

- 카테고리 색상
- 종일/시간 없음 항목의 대략적인 순서
- 시간 항목의 세로 위치
- 같은 시간대 항목의 겹침
- 표시 한도를 넘는 항목의 `+N` 개수

좁은 패널은 미리보기 전용이다. 개별 항목을 누르거나 완료 상태를 바꾸지 않으며,
패널 전체를 누르면 해당 패널이 확대된다.

## 5. 스크롤과 고정 영역

날짜 헤더와 종일/시간 없음 요약은 세로 스크롤에서 제외한다. Calendar와 Todo의
시간 영역은 하나의 세로 스크롤 위치를 공유한다. 따라서 어느 패널 위에서
스크롤하더라도 두 패널의 같은 시간선이 항상 수평으로 정렬된다.

빈 날짜에는 별도 장식 카드를 넣지 않는다. 흰 배경과 시간선만 유지하며 좁은
패널에도 `0` 배지를 표시하지 않는다.

## 6. 확장형 FAB

상단 앱 메뉴는 사용하지 않는다. 넓게 열린 패널의 오른쪽 아래에 남색 확장형
FAB 하나를 표시한다. FAB를 누르면 위쪽으로 아래 네 항목이 펼쳐진다.

- 새 항목 추가
- 루틴 관리
- 카테고리 관리
- 설정

`새 항목 추가`는 일정 추가와 Todo 추가를 별도 메뉴로 나누지 않는다. 하나의
추가 화면에 진입한 뒤 화면 안에서 일정 또는 Todo 유형을 선택한다.

로그아웃은 FAB에 직접 노출하지 않고 설정 화면 안에 둔다. 바깥 영역을 누르거나
FAB를 다시 누르면 메뉴가 닫힌다. 좁은 패널에는 FAB를 표시하지 않는다.

## 7. 컴포넌트 경계

- `DailySplitPage`: 선택 날짜의 비동기 상태와 사용자 동작을 연결한다.
- `SharedDateHeader`: 날짜 표시와 이전·다음 날짜 이동만 담당한다.
- `DailySplitViewport`: 두 패널의 너비, 가로 드래그, 스냅을 담당한다.
- `DailyPinnedSummary`: 종일 일정과 시간 없는 Todo의 고정 행을 배치한다.
- `DailyTimeline`: 하나의 세로 스크롤 안에 두 시간 패널을 배치한다.
- `CalendarPane`: Calendar의 넓은/좁은 표현을 제공한다.
- `TodoPane`: Todo의 넓은/좁은 표현과 넓은 상태의 완료 토글을 제공한다.
- `ExpandableMenuFab`: 네 전역 메뉴를 표시하고 선택 결과를 상위 셸에 전달한다.

각 패널은 같은 `TodayOverview` 데이터를 사용한다. 넓은 표현과 좁은 표현은
별도 위젯이지만 필터링과 시간 위치 계산 결과를 공유해 항목 수와 위치가
어긋나지 않게 한다. 기존 저장소, use case, `TodayViewModel`의 날짜 조회와
낙관적 Todo 완료 토글은 유지한다.

## 8. 상태와 오류

날짜가 바뀌면 `TodayViewModel`이 해당 날짜를 한 번 조회하고 두 패널을 동시에
갱신한다. 로딩 중에도 공유 날짜 헤더는 유지한다. 조회 오류가 발생하면 화면
구조를 유지하고 본문에 오류 메시지와 재시도 동작을 제공한다.

Todo 완료 토글 실패는 기존 동작처럼 낙관적 변경을 되돌리고 SnackBar로 알린다.
패널 전환 상태와 FAB 열림 상태는 화면 표시 상태이므로 영속화하지 않는다.

## 9. 접근성과 시각 규칙

- 배경과 주요 셸은 흰색을 유지한다.
- 의미 강조는 카테고리 색상에 한정한다.
- 시간 구분선은 얇은 중립색 점선 또는 실선으로 표시한다.
- 터치 가능한 날짜 화살표, 넓은 Todo 체크박스, FAB는 최소 터치 영역을 확보한다.
- 좁은 패널은 개별 항목 semantics를 노출하지 않고 패널 전환 동작만 설명한다.
- 시스템 글자 크기가 커져도 날짜 이동과 패널 전환이 가려지지 않아야 한다.

## 10. 검증 범위

- 이전·다음 날짜 이동과 두 패널의 공유 날짜
- 82:18, 18:82 안정 상태와 드래그 스냅
- 좁은 패널 탭 확대
- 날짜 헤더와 고정 요약의 비스크롤 동작
- 두 시간 패널의 세로 위치 정렬
- 좁은 패널의 색상 블록, 겹침, `+N`
- 넓은 Todo의 완료 토글과 실패 복원
- 확장형 FAB의 네 메뉴와 통합 추가 진입
- 상단 메뉴와 좁은 패널 FAB가 표시되지 않음
- 빈 날짜, 항목 과다, 모바일 너비, 큰 시스템 글자
- 최종 모바일·웹 스크린샷
