# 새 항목 시간 입력 설계

## 목표

통합 새 항목 화면에서 일정과 Todo의 시간 형태를 선택하고 시작·종료 시각을
입력할 수 있게 한다. 이번 변경은 화면의 입력 상태와 시간 범위 검증까지만
담당하며 카테고리, 알림, 반복, 실제 저장은 포함하지 않는다.

## 선택한 접근

한 화면 안에서 종류별 시간 형태를 짧은 선택 버튼으로 전환하고, 시간 지정
상태에서만 시작·종료 버튼을 노출한다. 별도 단계형 화면은 입력 흐름이 길어지고,
자유 형식 시간 입력은 모바일 접근성과 검증 부담이 커지므로 사용하지 않는다.

## 입력 규칙

- 일정의 기본 시간 형태는 `시간 지정`이며 `종일`로 전환할 수 있다.
- Todo의 기본 시간 형태는 `시간 없음`이며 `시간 지정`으로 전환할 수 있다.
- 시작·종료 시각에는 임의 기본값을 넣지 않고 사용자가 직접 선택한다.
- 선택 날짜는 기존 Daily 날짜로 고정하며 시간 선택은 그 날짜 안에서만 다룬다.
- 종류를 전환해도 제목과 이미 선택한 시각은 유지한다.
- `종일` 또는 `시간 없음` 상태에서는 시간 입력 행을 숨긴다.
- 다시 `시간 지정`으로 돌아오면 이전에 선택한 시각을 복원한다.

## 검증과 저장 버튼

- 시작과 종료가 모두 선택된 경우에만 시간 범위를 비교한다.
- 종료 시각이 시작 시각과 같거나 빠르면 `종료 시간은 시작 시간보다 늦어야 합니다.`를
  시간 입력 바로 아래에 표시한다.
- 한쪽 시각만 선택한 상태는 입력 중인 상태로 보고 오류를 표시하지 않는다.
- 이번 PR에서는 실제 저장을 연결하지 않으므로 상단 저장 버튼은 계속 비활성이다.

## 구조

- `NewItemScheduleDraft`가 일정/Todo별 시간 형태, 선택 시각과 범위 오류를 관리한다.
- `NewItemPage`는 종류 전환과 시간 선택 UI를 조합하고 draft를 화면 상태로 보유한다.
- 시각은 날짜와 분리된 `TimeOfDay`로 관리해 이 단계에서 도메인 저장 모델을 만들지 않는다.
- 시간 버튼은 현재 값을 `오전 9:00` 형식으로 보여주고 스크린리더에도 역할과 값을 제공한다.

## 테스트

- 순수 상태 테스트로 종류별 기본값, 형태 전환, 시각 보존과 범위 오류를 검증한다.
- 위젯 테스트로 일정/Todo별 선택 버튼, 조건부 시간 행, 시간 선택 결과와 오류 문구를 검증한다.
- 390px 폭과 큰 글자에서도 세로 스크롤로 모든 입력에 도달할 수 있어야 한다.
- 전체 Flutter 테스트와 분석을 실행하고 모바일 웹 화면을 캡처한다.

## PR 경계

설계, 계획, 상태/테스트, 화면/테스트, 모바일 시각 증거만 한 PR에 포함한다.
실제 저장, 카테고리 조회·선택, 알림과 반복은 후속 PR로 남긴다.
