# Today 화면 재설계

> 상태: 승인된 구현 설계
> 기준 문서: `docs/PRODUCT_SPEC.md`
> 시각 기준: `docs/design/reference/today-date-canvas.png`
> 대상 플랫폼: Flutter Android / iOS / Web

## 1. 목표

기존의 데스크톱형 `Task Dock + Timeline` 좌우 분할 일력 화면을 폐기하고,
모바일 우선 한 컬럼 Today 화면을 새로 구현한다. 화면은 로컬 Drift 데이터를
사용하며 선택 날짜, 지난 미완료, 종일 일정, 시간 지정 항목, 시간 없는 투두,
완료 투두를 중복 없이 보여준다.

구현은 리뷰 가능한 크기를 유지하기 위해 두 개의 스택형 PR로 나눈다.

1. `codex/today-data-foundation`: 데이터 모델, Drift 마이그레이션, 조회 계약
2. `codex/today-page`: Today UI, 전역 캘린더 셸, 상호작용, 시각 증거

첫 PR은 `main`을 대상으로 한다. 두 번째 PR은 첫 PR 브랜치를 대상으로 열어
UI 변경만 독립적으로 검토할 수 있게 하며, 첫 PR이 병합되면 대상을 `main`으로
변경한다. 두 PR 모두 병합은 동료 리뷰 후 사용자가 수행한다.

## 2. 제외 범위

이번 두 PR에는 다음을 포함하지 않는다.

- 실제 일정/투두 작성 및 편집 폼
- 루틴 관리, 카테고리 관리, 설정 화면의 본문
- Week 및 Month 본문 재설계
- Timeline 드래그, 블록 리사이즈, 데스크톱 전용 다중 패널
- 자동 이월, 원격 동기화, 알림 예약

전역 `+`와 상단 관리 메뉴는 올바른 진입 항목을 노출한다. 아직 본문 화면이 없는
항목을 선택하면 현재 범위가 아님을 명확히 알리고 원래 화면을 유지한다.

## 3. 데이터 모델

물리 테이블과 기존 `Task` 이름은 마이그레이션 안정성을 위해 유지하되, 하나의
행이 일정인지 투두인지 명시한다.

### 3.1 새 필드

- `kind`: `event` 또는 `todo`
- `targetDate`: 항목이 속한 로컬 날짜의 자정 값

기존 필드는 다음 의미로 사용한다.

- `hasTime`: 시작/종료 시각이 있는지 나타낸다.
- `startDateTime`, `endDateTime`: 시간 지정 항목에만 존재한다.
- `isAllDay`: 종일 일정에만 `true`다.
- `isCompleted`: 투두에만 의미가 있으며 일정은 항상 `false`다.
- `categoryId`: 일정과 투두가 공유하는 선택적 카테고리 참조다.

### 3.2 유효성 규칙

- 모든 항목은 `targetDate`를 가진다.
- 시간 지정 항목은 시작과 종료 시각을 모두 가진다.
- 종료 시각은 시작 시각보다 늦어야 한다.
- 시작 시각의 로컬 날짜는 `targetDate`와 같아야 한다.
- 종일 항목은 `event`만 허용하며 시간 필드를 사용하지 않는다.
- `event`는 완료 상태를 가질 수 없다.

생성·수정 UseCase가 이 규칙을 검증하고 Repository 이하 계층은 유효한 입력만
받는다. Repository는 기존 계약대로 예외 대신 `Result<T>`를 반환한다.

### 3.3 Drift 마이그레이션

데이터베이스 스키마를 1에서 2로 올리고 `kind`, `targetDate` 열을 추가한다.
기존 행은 다음 규칙으로 보존한다.

- `isAllDay == true`인 행은 `event`, 나머지는 `todo`로 변환한다.
- `targetDate`는 `startDateTime`의 로컬 날짜를 우선 사용한다.
- 시작 시각이 없으면 `createdAt`의 로컬 날짜를 사용한다.
- 변환 뒤 모든 날짜는 자정으로 정규화한다.
- 종일 일정은 완료 상태와 시간 필드를 제거한다.
- 시간 지정 행에 유효한 시작·종료 쌍이 없으면 시간 없는 투두로 보존한다.

신규 설치에는 처음부터 새 스키마와 기본 카테고리를 생성한다. 마이그레이션은
기존 행의 ID, 제목, 카테고리, 완료 상태와 생성 시각을 보존한다.

## 4. Today 조회 계약

새 `GetTodayOverviewUseCase`는 선택 날짜 하나를 받아 `TodayOverview`를 반환한다.
이 UseCase가 Task Repository와 Category Repository를 함께 사용해 항목과 선택적
카테고리를 조합한다. Task 조회는 한 번의 일관된 흐름으로 수행하며 기존
Day/TaskDock ViewModel처럼 서로 다른 상태 객체가 같은 데이터를 중복 조회하지
않는다.

`TodayOverview`는 다음 목록을 가진다.

- `overdueTodos`: `targetDate`가 선택 날짜보다 이전이고 완료되지 않은 모든 투두
- `allDayEvents`: 선택 날짜의 종일 일정
- `timelineItems`: 선택 날짜의 시간 지정 일정과 미완료 시간 지정 투두
- `untimedTodos`: 선택 날짜의 시간 없는 미완료 투두
- `completedTodos`: 선택 날짜의 완료된 모든 투두

각 항목은 정확히 하나의 목록에만 속한다. 특히 완료한 시간 지정 투두는
Timeline에서 제거하고 완료 목록에만 둔다. 목록 정렬은 아래와 같이 고정한다.

- 지난 미완료: `targetDate`, 생성 시각, 안정적인 ID 순
- 종일 일정: 카테고리 `sortOrder`, 생성 시각, ID 순
- Timeline: 시작 시각, 종료 시각, ID 순
- 시간 없는 투두: 카테고리 `sortOrder`, 생성 시각, ID 순
- 완료 투두: 완료 여부 변경 시각이 현재 모델에 없으므로 생성 시각, ID 순

각 목록은 Task와 선택적 Category를 가진 `TodayEntry`로 구성한다. 존재하지 않는
카테고리 ID는 카테고리 없음으로 안전하게 처리하며 정렬에서는 마지막에 둔다.

## 5. 화면 구조

`DayViewPage`와 좌우 분할 플레이스홀더를 `TodayPage`로 교체한다. Android, iOS,
Web 모두 동일한 한 컬럼을 사용하고 넓은 Web에서는 가운데 정렬과 최대 폭만
적용한다.

화면의 세로 순서는 고정한다.

1. 날짜 헤더
2. 지난 미완료 투두 트레이
3. 종일 일정
4. 압축형 세로 Timeline
5. 시간 없는 투두
6. 완료된 투두

### 5.1 날짜 헤더

- 연·월과 선택 날짜를 명확히 표시한다.
- 이전 날, 오늘, 다음 날 이동을 제공한다.
- 선택 날짜를 중심으로 한 7일 스트립을 제공한다.
- 날짜 선택은 공유 `selectedDateProvider`만 변경한다.
- 날짜는 시간 경과로 자동 변경하지 않는다.

### 5.2 지난 미완료

- 기본은 접힌 상태다.
- 개수와 가장 오래된 날짜를 요약한다.
- 펼치면 원래 날짜와 제목을 보여준다.
- 항목은 오늘로 자동 이동하지 않는다.

### 5.3 종일 일정

- 항목이 없으면 섹션 전체를 접어 불필요한 빈 공간을 만들지 않는다.
- 항목이 있으면 카테고리 색상을 사용한 한 줄 카드로 표시한다.
- 체크박스를 표시하지 않는다.

### 5.4 Timeline

- 24시간 전체 높이의 그리드를 사용하지 않는다.
- 레퍼런스처럼 실제 항목 주변을 빠르게 훑는 압축형 세로 Timeline을 사용한다.
- 시작 시각은 굵고 선명하게, 종료 시각은 보조 정보로 표시한다.
- 일정에는 체크박스가 없고 시간 지정 투두에만 체크박스가 있다.
- 겹치는 항목도 세로 읽기 순서를 유지하며 가로 다중 열로 압축하지 않는다.

### 5.5 시간 없는 투두와 완료 투두

- 시간 없는 투두는 체크박스, 제목, 카테고리, 선택적 보조 정보를 표시한다.
- 완료 투두는 기본적으로 접힌 상태다.
- 완료된 시간 지정 투두와 시간 없는 투두를 한 완료 섹션에 모은다.
- 동일 항목을 Timeline이나 미완료 목록에 중복 표시하지 않는다.

## 6. 전역 캘린더 셸

기존 상단 Day/Week/Month 분할 버튼을 제거하고 하단 내비게이션을 사용한다.

- `오늘`: `/calendar/today`
- `주간`: 기존 Week 화면
- `월간`: 기존 Month 화면

기존 `/calendar/day` 링크는 `/calendar/today`로 리다이렉트해 호환성을 유지한다.
로그인 성공과 세션 복원도 Today 경로로 진입한다.

상단 메뉴에는 `루틴 관리`, `카테고리 관리`, `설정`, `로그아웃`을 둔다.
로그아웃은 현재 인증 흐름을 그대로 보존한다. 전역 `+`는 `일정 추가`,
`투두 추가` 두 항목만 제공한다. 작성/관리 본문이 없는 항목은 후속 범위임을
Snackbar로 알리고 잘못된 빈 경로로 이동하지 않는다.

## 7. 상태와 상호작용

`TodayViewModel` 하나가 공유 선택 날짜와 Today 본문 상태를 관리한다.

- 날짜 변경: 새 날짜 헤더를 즉시 반영하고 본문은 로딩 상태로 바꾼다.
- 조회 성공: `TodayOverview`와 카테고리를 화면 전용 항목으로 조합한다.
- 조회 실패: 오류 메시지와 `다시 시도` 동작을 제공한다.
- 지난 미완료/완료 섹션: 기본 접힘, 사용자 동작으로만 펼친다.
- 날짜 변경: 두 접힘 상태를 기본값으로 초기화한다.
- 투두 완료: 화면에 낙관적으로 반영하고 Drift 저장 실패 시 원래 상태로
  되돌린 뒤 Snackbar로 알린다.

이전 날짜의 항목을 새 날짜 헤더 아래에 잠시 남겨두지 않는다. 빈 섹션은 큰
플레이스홀더 대신 짧은 안내 문구를 사용하거나 섹션을 접는다.

## 8. 코드 경계

새 UI는 한 파일에 몰아넣지 않고 다음 책임으로 나눈다.

- Today overview 도메인 모델과 UseCase: 분류·정렬·중복 방지
- Today ViewModel/State: 로딩, 오류, 접힘, 완료 처리
- Today page: 섹션 조합과 최대 폭 레이아웃
- 날짜 헤더: 날짜 이동과 7일 스트립
- 지난 미완료 트레이: 접기/펼치기
- 종일 일정 섹션: 이벤트 카드
- Timeline: 시간 라벨과 일정/투두 행
- 투두 섹션: 미완료/완료 목록
- Calendar shell: 하단 탭, 상단 메뉴, 전역 추가 버튼

기존 `day_view_state`, `task_dock_state`, 두 ViewModel과 생성 파일은 새 화면이
사용되지 않음을 확인한 뒤 UI PR에서 제거한다. 데이터·Repository 구조 중 새
계약과 맞는 부분은 유지하고 좌우 분할 전용 동작만 제거한다.

## 9. 오류 처리

- DataSource는 Drift 오류를 `CacheException`으로 변환해 throw한다.
- Repository는 이를 `CacheFailure`로 변환해 `Result<T>`로 반환한다.
- UseCase 유효성 오류는 명확한 실패 메시지로 반환한다.
- ViewModel은 조회 실패를 화면 오류 상태로, 변경 실패를 복구 가능한 Snackbar로
  구분한다.
- 오류 화면의 재시도는 현재 선택 날짜를 다시 조회한다.

## 10. 테스트와 시각 검증

### 10.1 데이터 PR

- 스키마 1에서 2로 마이그레이션하고 기존 행을 보존하는 통합 테스트
- 신규 설치 스키마 테스트
- 일정/투두 생성·수정 유효성 테스트
- 선택 날짜별 항목 조회 테스트
- 지난 미완료 계산 테스트
- 다섯 목록의 분류, 정렬, 중복 방지 테스트

### 10.2 UI PR

- 날짜 이전/오늘/다음과 7일 스트립 테스트
- 정해진 섹션 순서와 빈 상태 테스트
- 지난 미완료 및 완료 섹션 접기/펼치기 테스트
- 시간 지정 투두가 Timeline과 완료 섹션에 중복되지 않는지 테스트
- 투두 완료 성공과 실패 복구 테스트
- 오류 및 재시도 테스트
- 하단 탭, 상단 메뉴, 전역 `+`, 로그아웃 회귀 테스트
- 390x844 모바일과 넓은 Web 크기에서 오버플로가 없는지 테스트

실제 Chrome에서 모바일과 넓은 Web 화면을 확인한다. UI PR에는 결정적 fixture로
채운 실제 Today 위젯과 빈 상태의 스크린샷을
`docs/design/evidence/pr-XX-today-page/`에 커밋하고 PR 본문에 직접 삽입한다.
스크린샷용 fixture는 테스트/검증 경계에만 존재하며 운영 앱 데이터를 시드하지
않는다.

## 11. 완료 기준

- 기존 좌우 분할 Day UI가 사용자 경로에서 완전히 제거된다.
- Today가 명세의 여섯 섹션을 한 컬럼으로 표시한다.
- 일정과 투두, 날짜와 완료 상태가 Drift에서 영속화된다.
- 모든 항목은 정확히 하나의 Today 섹션에만 나타난다.
- 로그인, 세션 복원, 로그아웃 흐름이 유지된다.
- Android/iOS/Web 공통 레이아웃과 넓은 Web 최대 폭 규칙이 지켜진다.
- 자동화 테스트, 정적 분석, Web release build, 실제 브라우저 검증을 완료한다.
- 모든 커밋은 파일 한 개만 변경한다.
- 두 PR 모두 동료가 검토할 수 있는 설명과 실제 시각 증거를 포함한다.
