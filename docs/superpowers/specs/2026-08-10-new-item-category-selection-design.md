# 새 항목 카테고리 선택 설계

## 목표

통합 새 항목 화면에서 일정과 Todo에 공통으로 사용할 카테고리를 선택할 수
있게 한다. 이번 변경은 저장된 카테고리의 조회와 입력 상태 선택까지만 담당하며
카테고리 관리와 실제 항목 저장은 포함하지 않는다.

## 선택한 접근

입력 화면에는 현재 선택값을 색상 점과 이름으로 한 줄만 표시하고, 누르면
하단 선택창을 연다. 모든 카테고리를 폼 안에 칩으로 펼치는 방식은 항목 수가
늘수록 화면이 길어지고, 일반 드롭다운은 카테고리 색상을 빠르게 구분하기
어려우므로 사용하지 않는다.

## 표시와 선택 규칙

- `카테고리` 입력은 제목과 시간 사이에 배치한다.
- 기본값은 `카테고리 없음`이며 카테고리 선택은 선택 사항이다.
- 저장된 카테고리는 저장소가 반환한 `sortOrder` 순서로 표시한다.
- 각 선택 항목은 색상 점과 이름을 함께 표시해 색상만으로 의미를 전달하지 않는다.
- 현재 항목에는 체크 표시와 선택 semantics를 함께 제공한다.
- 항목을 누르면 선택값을 반영하고 하단 선택창을 닫는다.
- 일정과 Todo 사이를 전환해도 선택한 카테고리는 유지한다.

## 조회 상태

- 화면 진입 시 기존 `GetCategoriesUseCase`로 카테고리를 한 번 조회한다.
- 로딩 중에는 카테고리 행에 `카테고리 불러오는 중`을 표시하고 선택을 막는다.
- 조회 실패 시 `카테고리를 불러오지 못했습니다.`와 `다시 시도`를 같은 영역에
  표시한다.
- 재시도는 같은 use case를 다시 호출하며 성공하면 정상 선택 행으로 교체한다.
- 저장된 카테고리가 없어도 `카테고리 없음`은 선택할 수 있다. 카테고리 생성
  유도나 관리 화면 이동은 이번 범위에 넣지 않는다.

## 구조

- `NewItemCategoryState`가 로딩, 성공 목록과 실패 메시지를 immutable 상태로
  관리한다.
- 상태는 목록을 `sortOrder`, 동률이면 ID 순서로 안정적으로 정렬하고 존재하지
  않는 선택 ID를 조회할 때 `카테고리 없음`으로 정규화한다.
- `NewItemPage`는 선택 ID를 보유하고 `NewItemCategoryInput`의 변경 callback을
  반영한다.
- `NewItemCategoryInput`은 Riverpod의 `GetCategoriesUseCase`를 호출하고 하단
  선택창까지 담당해 폼 페이지의 책임과 크기를 줄인다.
- 테스트에서는 실제 데이터베이스 대신 조회 callback을 주입해 로딩, 성공, 실패,
  재시도를 결정적으로 검증한다.

## 접근성과 반응형

- 선택 행은 `카테고리, 현재값` 형식의 버튼 semantics를 제공한다.
- 하단 선택창은 제목과 radio 역할을 제공하고 현재 선택 상태를 노출한다.
- 색상 점에는 이름이 함께 있으므로 색상 인지에 의존하지 않는다.
- 390px 폭과 큰 글자에서도 폼은 세로 스크롤되고 선택창 항목은 잘리지 않아야 한다.

## 테스트

- 순수 상태 테스트로 정렬, 선택, 선택 해제, 종류 전환과 무관한 값 보존을 검증한다.
- 위젯 테스트로 로딩, 성공 선택, 빈 목록, 실패와 재시도, 접근성 label을 검증한다.
- 전체 Flutter 테스트와 분석을 실행하고 390x844 모바일 웹 화면을 캡처한다.

## PR 경계

설계, 계획, 카테고리 입력 상태/테스트, 선택 widget, 화면/테스트, 모바일 시각
증거만 한 PR에 포함한다. 변경 파일은 7개를 넘지 않으며 모든 파일은 각각 별도
커밋한다. 실제 저장, 카테고리 생성·수정·삭제, 알림과 반복은 후속 PR로 남긴다.
