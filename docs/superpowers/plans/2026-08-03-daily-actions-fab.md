# Daily Global Actions FAB Implementation Plan

**Goal:** 데일리 화면의 상단 앱바와 메뉴를 제거하고, 사용자가 그린 화면처럼
오른쪽 아래의 확장형 FAB 하나에서 전역 기능을 선택하게 한다.

**Architecture:** `CalendarShellPage`는 날짜 콘텐츠와 하단 내비게이션만 유지한다.
새 `ExpandableMenuFab` 위젯이 열림 상태, 애니메이션, 접근성, 메뉴 선택을 소유하고
셸은 선택 결과만 처리한다.

## PR 경계

이 PR은 `codex/daily-split-todo`를 base로 한다. 실제 일정·Todo 입력 화면과
루틴/카테고리 관리 화면은 포함하지 않는다. 다만 기존 로그아웃 진입점을 없애는
회귀를 막기 위해 `설정`은 로그아웃만 담은 최소 시트를 열고, 나머지 설정은 후속
작업으로 남긴다. 다른 미구현 메뉴는 후속 작업임을 알리는 메시지만 표시한다.

변경 파일은 계획, 위젯 테스트/구현, 셸 테스트/구현, 시각 증거를 합쳐 7개
이하로 제한한다. PR #7보다 훨씬 작은 단위로 유지한다.

## 동작과 시각 규칙

- `NAE MO` 앱바와 상단 더보기 메뉴를 제거한다.
- 오른쪽 아래 남색 정사각형 FAB 하나만 표시한다.
- FAB를 누르면 위쪽으로 `새 항목 추가`, `루틴 관리`, `카테고리 관리`, `설정`이
  차례로 펼쳐진다.
- 일정과 Todo는 별도 메뉴로 나누지 않고 `새 항목 추가` 하나로 진입한다.
- 로그아웃은 전역 메뉴에서 제거하고 최소 설정 시트 안으로 이동한다.
- 메뉴 밖이나 선택 항목을 누르면 메뉴가 닫힌다.
- 흰 배경, 중립색 구분선, 카테고리 색 중심의 기존 데일리 디자인을 유지한다.
- 큰 글자와 390px 모바일 폭에서도 overflow가 없어야 한다.

## TDD 순서

### 1. 확장형 FAB 위젯

- 닫힌 상태에는 주 FAB만 보이는 테스트를 먼저 추가한다.
- 주 FAB를 누르면 네 메뉴와 접근성 레이블이 나타나는 테스트를 추가한다.
- 메뉴 선택, 재클릭, 바깥 탭으로 닫히는 테스트를 추가한다.
- 테스트 실패를 확인한 뒤 위젯을 구현한다.

### 2. CalendarShell 연결

- 앱바와 기존 팝업/추가 바텀시트가 사라지는 셸 테스트를 먼저 수정한다.
- 네 전역 메뉴가 현재 라우트를 유지하며 후속 작업 메시지를 표시하는지 검증한다.
- 설정 시트 안의 로그아웃 성공/실패 흐름을 회귀 테스트한다.
- 셸의 인증 의존성은 설정 시트의 로그아웃에만 남기고 새 FAB callback을 연결한다.

### 3. 검증과 증거

- 변경 Dart 파일 format/analyze
- 전체 `flutter test`
- Flutter web 390px/1200px에서 닫힘/펼침 상태 확인
- 브라우저 렌더링 오류 확인
- 모바일·웹 이미지를 각각 한 파일씩 커밋
- 변경 파일과 diff 크기를 확인한 뒤 스택 PR 생성
