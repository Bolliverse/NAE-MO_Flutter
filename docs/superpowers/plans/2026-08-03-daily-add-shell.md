# Unified New Item Shell Implementation Plan

**Goal:** 확장형 FAB의 `새 항목 추가`가 하나의 화면을 열고, 그 안에서 일정과
Todo를 선택하며 현재 Daily 날짜를 고정해 보여준다.

**Architecture:** 일정과 Todo가 모두 `Task` 도메인을 사용하므로 새 화면은
`features/task/presentation/pages`에 둔다. 루트 라우터가 캘린더 셸 바깥에서
화면을 열어 입력 중에는 하단 내비게이션과 FAB가 중복되지 않게 한다.

## PR 경계

이 PR은 `codex/daily-actions-fab`을 base로 한다. 화면 진입/닫기, 일정·Todo 종류
선택, 선택 날짜 표시, 공통 제목 입력까지만 포함한다. 카테고리, 종일/시간,
반복, 실제 저장과 Today 갱신은 다음 PR로 분리한다.

변경 파일은 계획, 화면 테스트/구현, 앱 라우팅 테스트/구현, FAB 연결, 모바일
시각 증거를 합쳐 7개 이하로 제한한다.

## 동작과 시각 규칙

- FAB의 `새 항목 추가`를 누르면 전체 화면 입력 셸을 연다.
- 상단에는 닫기, `새 항목 추가`, 비활성 `저장`만 둔다.
- 일정과 Todo는 같은 화면의 두 탭으로 전환한다.
- 기본 종류는 일정이며 전환해도 입력한 제목은 유지한다.
- 날짜는 Daily에서 선택한 날짜를 그대로 보여주고 이 PR에서는 변경하지 않는다.
- 흰 배경, 얇은 중립색 선, 남색 선택 상태만 사용한다.
- 입력 화면에서는 캘린더 하단 내비게이션과 전역 FAB를 숨긴다.
- 뒤로가기/닫기는 기존 Daily 화면과 선택 날짜를 보존한다.

## TDD 순서

### 1. NewItemPage 화면

- 고정 날짜, 기본 일정 선택, 공통 제목 입력, 비활성 저장을 테스트한다.
- Todo 전환과 제목 보존을 테스트한다.
- 닫기 callback과 390px 큰 글자 overflow를 테스트한다.
- 실패를 확인한 뒤 화면을 구현한다.

### 2. 라우터와 FAB 연결

- 인증 사용자가 FAB 메뉴에서 새 화면으로 이동하는 앱 테스트를 추가한다.
- 입력 화면에서 하단 내비게이션/FAB가 사라지고 닫으면 Today로 복귀하는지
  검증한다.
- 루트 라우트와 FAB callback을 연결한다.

### 3. 검증과 증거

- 변경 Dart 파일 format/analyze
- 전체 `flutter test`
- Flutter web 390px에서 일정/Todo 선택과 날짜 확인
- 브라우저 렌더링 오류 확인
- 모바일 이미지 한 파일 커밋
- 7개 파일/변경 줄 경계를 확인해 스택 PR 생성
