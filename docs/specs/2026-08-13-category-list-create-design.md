# 카테고리 목록 및 생성 화면 설계

## 목표

전역 FAB의 `카테고리 관리` 메뉴를 실제 화면으로 연결하고, 사용자가 현재 카테고리를
확인하거나 새 카테고리를 이름과 색상으로 만들 수 있게 한다. 새로 만든 카테고리는 다음
항목 추가부터 바로 선택할 수 있어야 한다.

## 이번 PR 범위

- FAB의 `카테고리 관리`에서 별도 전체 화면으로 이동한다.
- 진입 전 Today/Week/Month 위치를 기억하고 닫을 때 같은 화면으로 돌아간다.
- 카테고리 목록을 `sortOrder`, ID 순서로 안정적으로 표시한다.
- 이름과 색상을 고르는 생성 바텀시트를 제공한다.
- 생성 성공 시 바텀시트를 닫고 반환된 카테고리를 목록에 즉시 추가한다.
- 조회 및 생성 실패 시 입력을 잃지 않는 재시도 가능한 오류를 표시한다.

카테고리 수정, 삭제, 순서 변경, 사용 개수 표시는 후속 PR로 남긴다.

## 화면 구조

관리 화면은 캘린더 셸 밖에서 열어 FAB와 하단 탭을 숨긴다.

1. 상단: 닫기 버튼과 `카테고리 관리` 제목
2. 안내: 카테고리 색상이 일정과 Todo에 표시된다는 짧은 설명
3. 본문: 색상 점과 이름만 있는 단순 목록
4. 하단: 네이비색 `새 카테고리` 버튼

목록이 비었을 때는 장식성 카드를 추가하지 않고, 짧은 빈 상태 문구와 하단 버튼만
유지한다. 배경은 흰색이며 카테고리 색상 외의 강조색은 Daily 네이비를 사용한다.

## 생성 바텀시트

바텀시트에는 다음 요소만 둔다.

- `이름` 텍스트 필드
- 8개의 고정 색상 팔레트
- `취소`, `생성` 액션

이름은 저장 직전에 trim한다. trim 결과가 비어 있으면 생성 버튼을 비활성화한다.
첫 번째 색상을 기본 선택하며, 선택된 색상은 네이비 외곽선과 체크로 구분한다.

저장 중에는 입력, 색상, 취소, 중복 제출을 잠근다. 성공하면 반환된 `Category`를 목록에
추가하고 시트를 닫는다. 실패하거나 예외가 발생하면 이름과 색상을 유지한 채 시트 안에
`카테고리를 만들지 못했습니다. 다시 시도해 주세요.`를 표시한다.

## 데이터 흐름

- 조회: 기존 `GetCategoriesUseCase`
- 생성: 기존 `CreateCategoryUseCase`
- 화면 테스트: loader와 creator callback을 주입
- 앱 실행: callback이 없으면 Riverpod provider에서 기존 UseCase를 읽음

별도 ViewModel이나 새 저장 계층은 추가하지 않는다. 이 화면의 로컬 조회/제출 상태만
`ConsumerStatefulWidget`이 소유한다.

## 라우팅

- 새 경로: `/categories`
- FAB 진입 시 `from` 쿼리에 현재 Today/Week/Month 경로를 넣는다.
- 닫기 및 시스템 뒤로가기는 검증된 `from` 경로로 복귀한다.
- 인증되지 않은 접근은 기존 라우터 redirect 규칙에 따라 로그인으로 이동한다.

## 오류와 접근성

- 조회 실패: 전체 화면 오류와 `다시 시도` 버튼
- 생성 실패: 바텀시트 내 live region 오류
- 로딩과 생성 진행 상태: live region 및 명시적 진행 문구
- 카테고리 행: `카테고리 이름, 색상` 의미를 제공
- 색상 버튼: 색상 이름, 선택 상태, 상호 배타적 선택 의미를 제공
- 390px 모바일과 큰 글자에서도 가로 overflow가 없어야 한다.

## 테스트 경계

- 목록 정렬, 로딩, 빈 상태, 조회 실패와 재시도
- 이름 trim, 색상 전달, 생성 버튼 유효성
- 생성 중 중복 제출 방지
- 실패 시 입력 유지와 재시도
- 성공 시 반환된 카테고리 즉시 표시
- FAB 진입과 Today/Week/Month 원위치 복귀
- 모바일 및 큰 글자 레이아웃
