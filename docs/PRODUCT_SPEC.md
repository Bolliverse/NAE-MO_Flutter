# NAE-MO 제품 명세

> 상태: 현재 기준 제품 기준서
> 기준일: 2026-07-31
> 대상: Flutter Android / iOS / Web

## 1. 문서 역할

이 문서는 NAE-MO의 현재 제품 동작을 정의하는 **정본 제품 명세**다.

- `docs/DEV_SPEC.md`, `docs/PHASE_3_PLAN.md`의 제품 결정은 이 문서로 대체한다.
- `docs/ARCHITECTURE.md`의 레이어링, 상태관리, Repository, DataSource 분리는 참고 가치가 있으며, 제품 동작과 충돌하지 않는 범위에서 유지한다.

## 2. 제품 원칙

- 모바일 우선이다.
- Android, iOS, Web 모두 **한 컬럼 중심 레이아웃**을 사용한다.
- Web도 데스크톱 전용 분할 패널을 추가하지 않는다.
- 기능 추가보다 **일관된 일정 관리 흐름**을 우선한다.
- 로컬 우선이다. 네트워크가 없어도 핵심 일정 관리가 동작해야 한다.

## 3. 전역 구조

### 3.1 하단 전역 탭

앱의 기본 화면 구조는 하단 3탭이다.

- `Today`
- `Week`
- `Month`

세 화면은 하나의 공유 선택 날짜를 사용한다.

### 3.2 상단 메뉴

상단 메뉴에는 아래 항목만 둔다.

- `루틴 관리`
- `카테고리 관리`
- `설정`

`루틴`과 `카테고리`는 하단 탭이 아니라 상단 메뉴 진입 항목이다.

### 3.3 전역 추가 버튼

전역 `+` 버튼은 아래 두 항목만 제공한다.

- `일정 추가`
- `투두 추가`

`루틴 추가`는 전역 `+`에 넣지 않는다. 루틴 생성은 `루틴 관리` 화면에서 시작한다.

## 4. 핵심 객체

### 4.1 일정

- 시간 기반 또는 종일 일정이 될 수 있다.
- 시작/종료 시간이 있는 일정은 Timeline에 배치한다.
- 종일 일정은 Today/Week의 종일 섹션에 배치한다.

### 4.2 투두

- 시간 없는 투두 또는 시간 지정 투두가 될 수 있다.
- 시간 지정 투두는 일정처럼 Timeline에 한 번만 나타난다.
- 시간 없는 투두는 Today의 미지정 투두 섹션에 나타난다.

### 4.3 카테고리

- 일정과 투두 모두 카테고리를 가질 수 있다.
- 카테고리는 색상과 이름을 가진다.
- 카테고리 관리는 별도 화면에서 수행한다.

## 5. Today

Today는 이 앱의 기본 진입 화면이다.

### 5.1 레이아웃 순서

Today는 아래 순서를 고정한다.

1. 날짜 헤더
2. 지난 미완료 투두 트레이
3. 종일 일정
4. Timeline
5. 시간 없는 투두
6. 완료된 투두

### 5.2 날짜 헤더

- 선택 날짜를 명확히 보여준다.
- 이전 날, 오늘, 다음 날 이동을 제공한다.
- Today / Week / Month는 동일한 선택 날짜 상태를 공유한다.
- 날짜는 자동으로 바뀌지 않는다. 사용자 명시 동작으로만 바뀐다.

### 5.3 지난 미완료 투두

- 지난 날짜의 미완료 투두는 자동으로 오늘로 이동하지 않는다.
- 지난 미완료 투두는 별도 트레이에서 접기/펼치기로 보여준다.

### 5.4 Timeline

- 시간 라벨은 충분히 눈에 띄어야 한다.
- 일정과 시간 지정 투두는 Timeline 안에서만 보인다.
- 시간 지정 투두를 Timeline 아래 목록에 중복 표시하지 않는다.

### 5.5 완료된 투두

- 완료된 투두는 선택 날짜 내부에서만 접어서 보여준다.

## 6. Week

Week는 **7개 날짜 요약 행**으로 구성된 스캔형 화면이다.

### 6.1 구조

- 한 주의 7일을 각각 한 행으로 보여준다.
- 각 행은 선택 날짜로 점프하는 진입점이다.
- 편집은 Week에서 직접 하지 않는다.

### 6.2 각 행의 정보

각 날짜 행은 아래 수준까지만 보여준다.

- 날짜
- 오늘/선택 상태 표시
- 일정 요약 최대 2개
- 첫 미완료 투두 1개
- 필요 시 개수 요약

Week는 요약과 점프가 목적이다. Day식 세부 Timeline을 복제하지 않는다.

## 7. Month

Month는 날짜 그리드와 하단 미리보기로 구성한다.

### 7.1 상호작용

- 날짜 1회 탭: 해당 날짜 미리보기 선택
- 같은 날짜 2회 탭 또는 미리보기 열기 동작: Today로 진입

### 7.2 월 마커 규칙

Month의 날짜 셀은 카테고리별 상태를 **최대 4개**까지 보여준다.

- `+N` 표시는 사용하지 않는다.
- 초과 카테고리는 별도 오버플로 배지를 만들지 않는다.
- 표시 우선순위는 카테고리 `sortOrder`를 먼저 따르고, 동률이면 안정적인 ID 순서로 고정한다.

### 7.3 마커 모양

카테고리-날짜 조합마다 하나의 마커만 만든다.

- 해당 날짜에 일정만 있으면 `원`
- 해당 날짜에 투두만 있으면 `마름모`
- 해당 날짜에 일정과 투두가 함께 있으면 `둥근 사각형`

### 7.4 체크 상태

- 체크 표시는 **그 카테고리-날짜 조합에 투두가 1개 이상 있고, 그 투두가 모두 완료된 경우에만** 보여준다.
- 마름모 안의 체크는 회전된 도형 안에서도 똑바로 읽혀야 한다.

### 7.5 배치

- 1개, 2개, 3개, 4개 마커는 고정된 배치 규칙을 사용한다.
- Month는 카테고리 막대형 UI를 사용하지 않는다.

## 8. 추가/편집 흐름

### 8.1 일정 추가/편집

- 전역 `+`에서 진입할 수 있다.
- 종일 일정과 시간 지정 일정을 모두 지원한다.
- 카테고리 선택을 지원한다.
- 알림은 선택 사항이다. 기본 강제값을 넣지 않는다.
- 종료 시간이 시작 시간보다 빠르면 저장할 수 없다.

### 8.2 투두 추가/편집

- 전역 `+`에서 진입할 수 있다.
- 시간 지정 투두와 시간 없는 투두를 모두 지원한다.
- 카테고리 선택을 지원한다.
- 알림은 선택 사항이다. 기본 강제값을 넣지 않는다.

### 8.3 카테고리 관리

- 상단 메뉴에서만 진입한다.
- 카테고리 생성, 수정, 삭제를 지원한다.

## 9. 루틴과 반복 규칙

루틴은 일정 또는 투두를 반복 규칙으로 정의하는 상위 개념이다.

### 9.1 루틴 출력 타입

- `일정 루틴`
- `투두 루틴`

### 9.2 반복 규칙

반복 규칙은 아래를 지원한다.

- 매일
- 매주
- 매월
- 매년
- 사용자 정의 간격

주간 반복은 7개 요일 전체를 지원하며 주말도 포함한다.

### 9.3 기간 규칙

- 시작일은 필수다.
- 종료일은 선택 사항이다.

### 9.4 생성 방식

반복 루틴은 두 가지 생성 방식을 가진다.

- `전체 날짜에 바로 추가`
- `수동으로 추가`

규칙은 아래 제약을 가진다.

- 종료일이 있는 **bounded 루틴**은 자동 추가 또는 수동 추가를 선택할 수 있다.
- 종료일이 없는 **unbounded 루틴**은 반드시 수동 추가만 사용한다.

### 9.5 수동 후보

수동 추가 루틴은 날짜 범위 안에서 **가상 후보**를 계산한다.

- 가상 후보는 실제 일정/투두 행으로 저장되지 않는다.
- 가상 후보는 Today/Week/Month의 일반 결과 목록에 포함되지 않는다.
- 선택 날짜에서는 일반 항목과 구분된 `수동으로 추가` 후보 영역으로만 보여준다.
- 사용자가 후보를 확정한 뒤에만 실제 항목이 생성된다.
- 과거 날짜의 후보를 추가하지 않고 닫았더라도, 같은 날짜를 다시 열면 후보가 다시 나타난다.

### 9.6 알림 상속

- 루틴은 기본 알림 규칙을 가질 수 있다.
- 확정된 실제 발생 항목은 기본 알림 규칙을 상속할 수 있다.
- 개별 발생 항목에서 알림을 별도로 덮어쓸 수 있다.
- 확정되지 않은 수동 후보에는 알림을 붙이지 않는다.

### 9.7 편집 범위

반복 항목 편집은 아래 범위를 지원한다.

- 이 항목만
- 이 항목과 이후
- 전체 반복

## 10. 데이터, 인증, 동기화

### 10.1 저장

- 기본 저장소는 Drift다.
- 앱은 로컬 우선으로 동작한다.
- 네트워크 연결이 없어도 핵심 일정 기능이 동작해야 한다.

### 10.2 동기화

- 초기 제품 단계에서는 로컬 우선을 유지한다.
- 이후 단계에서 Supabase 동기화를 추가한다.
- 동기화 추가 후에도 로컬 모델이 기준이며, 동기화는 그 위에 얹는다.

### 10.3 인증

- 첫 인증 구현에는 Google 로그인과 Apple 로그인을 함께 포함한다.

### 10.4 알림

- 로컬 알림을 지원한다.
- 일정, 투두, 루틴 기본 알림과 개별 발생 항목 알림 override를 지원한다.
- Android/iOS는 예약된 로컬 알림을 지원한다.
- Web은 현재 탭이 열려 있을 때의 알림까지만 지원하며, 백그라운드 Push는 후속 범위로 둔다.
- Windows는 현재 출시 대상이 아니므로 알림 기능이 없어도 안전하게 동작하고 빌드되어야 한다.

## 11. 플랫폼 정책

- Android, iOS, Web 모두 같은 제품 구조를 유지한다.
- Web도 모바일 우선 한 컬럼 구조를 유지하며, 넓은 화면에서는 가운데 정렬과 최대 폭 제한만 허용한다.
- 데스크톱 전용 사이드바, 이중 패널, 드래그 중심 편집 모델은 현재 범위에서 제외한다.

## 12. 시각 검증 계약

모든 UI 변경 PR은 아래 시각 검증 계약을 따른다.

### 12.1 계획 기준

- 승인된 목업 또는 레퍼런스 이미지를 `docs/design/reference/` 아래에 둔다.
- 각 PR은 어떤 레퍼런스를 기준으로 구현했는지 명시한다.

### 12.2 실제 증거

- 구현 후 실제 스크린샷을 `docs/design/evidence/pr-XX-<slug>/` 아래에 커밋한다.
- PR 본문에는 커밋된 스크린샷을 직접 embed 한다.
- README 나 텍스트 목록만 남기고 실제 PNG를 생략하지 않는다.

### 12.3 PR 본문 필수 항목

각 UI PR 본문에는 아래를 포함한다.

- 사용한 계획 레퍼런스
- 실제 구현 스크린샷
- 이전 동작에서 무엇이 바뀌었는지 한 줄 설명
- 의도적으로 유지한 이전 동작이 있다면 그 이유

## 13. 현재 기준으로 제외하는 방향

아래 방향은 현재 제품 기준에서 제외한다.

- Day 좌우 분할 `Task Dock + Timeline`
- Week의 드래그 중심 압축 타임라인
- Month의 카테고리 막대형 셀
- Month의 `+N` 오버플로 배지
- 전역 `+` 안의 루틴 추가
- 데스크톱 전용 다중 패널
- 자동으로 오늘로 이월되는 지난 미완료 투두

## 14. 구현 판단 기준

구현 중 문서 간 충돌이 나면 아래 우선순위를 따른다.

1. 이 문서
2. 현재 승인된 PR/목업 레퍼런스
3. `docs/ARCHITECTURE.md`의 구조적 원칙
4. 이전 제품 문서
